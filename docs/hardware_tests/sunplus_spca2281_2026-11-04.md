# Sunplus SPCA2281 / XWF-1080P camera test

Manual test on November 4, 2026 (America/Los_Angeles), against Joshua commit
`74ecbcc618658358de2bbc9048fe9d60df7acadb`. This records the camera run performed
while adding the [Sunplus preset](../../config/config_preset/example/sunplus_spca2281.pbtxt).
It is a short test of one unit, not an endurance or model-wide qualification.

## Setup and procedure

- USB product description: `Sunplus Innovation Technology Inc. SPCA2281 Web Camera`.
- V4L2 product: `XWF-1080P: XWF-1080P`; capture node `/dev/video0`.
- Ubuntu 22.04 / ROS 2 Humble / x86_64 in the Joshua Docker environment.
- Ran `//ros2:camera_publisher` directly with node name `sunplus_camera_publisher`,
  node ID `1`, and the Sunplus preset. No actuator or board node was launched.
- Used ROS domain `114` and `ROS_LOCALHOST_ONLY=1`.
- Subscribed to `/sunplus_camera/image_raw` with a reliable rclpy subscription,
  depth 10, for a 12-second observation window including startup and discovery.
- Counted received messages using the subscriber's monotonic receipt times.
  Validated dimensions, encoding, and payload length, and saved a sample frame.
- Separately ran Joshua's `//ros2/utils:camera_subscriber` desktop preview and
  confirmed that it received and displayed images. Capture was stopped afterward.

The publisher's successful initialization log reported 640x480 and a negotiated
30 FPS. The observed message rate below is measured separately; negotiating a
rate does not establish that the device delivers it.

The configured capture format was MJPG; initialization applied it successfully.
A V4L2 format query during an earlier run also confirmed MJPG at 640x480.
Direct OpenCV comparisons at 640x480, requesting 30 FPS with a one-frame buffer,
captured 60 frames in 7.444 seconds with MJPG and 7.338 seconds with YUYV.
These measurements establish that the low capture rate also occurred outside
Joshua; they do not establish its underlying cause.

The config preset validation and perception factory tests passed in the Humble
Docker environment. They establish software checks separately from this manual
hardware evidence. Camera frames are not committed because they contain imagery
from the local environment; this document retains the measured summary.

## Scope and reproduction

Only 640x480 capture and RGB ROS output were verified. Although the camera
advertised larger modes, including 1920x1080, those modes were not exercised.
Jazzy, other hardware revisions, synchronization accuracy, and sustained
30 FPS operation were not verified.

For a new run, follow the [hardware rules](../../AGENTS.md#hardware-safety--read-this-first),
confirm the camera's capture index, build the publisher and viewer in the
matching Docker environment, and run the same preset. The preset remains the
configuration source of truth. A historical test does not establish that the
currently connected device is ready or grant permission to open it.
